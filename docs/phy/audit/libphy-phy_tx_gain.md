# Line audit: `libphy.a[phy_tx_gain.o]`

Artifact:
`_oracles/libphy.a`, SHA-256
`51497819736295c9b33d6775495dade4c6fb39db887edfe095608c670d9ae223`.

The member defines eight external code functions. Every instruction,
relocation, branch, loop and constant-table slice was inspected. All eight
functions have closed strict results: three have no register effect, two are
not ported, and three have complete-domain mismatches.

## `phy_bt_chan_pwr_interp`

Size `0x50`. Strict status: **NO-REGISTER-EFFECT**.

This pure helper reads three signed bytes and returns one signed byte. For
channels through 37 it interpolates between bytes zero and one around channel
12; above 37 it interpolates between bytes one and two. The multiply and
signed division use denominator 25 and a rounding bias of `-12` below or at
channel 12 and `+12` otherwise. The final result is truncated and
sign-extended from eight bits.

There is no MMIO, mutable global, or child call. No equivalent BT interpolation
helper exists in Rust.

## `phy_set_tx_gain_mem_new`

Size `0x130`. Strict status: **MISMATCH**.

The function reads the high byte of `0x20100408` once. Every zero first input
uses that byte as the memory base; every nonzero first input adds 32, with
byte wrapping. It accepts an unrestricted entry count and six independent
table/configuration pointers.

For every entry it:

1. reads one TX-baseband gain halfword;
2. calls `phy_txbbgain_to_index`;
3. copies four halfwords from the selected eight-byte seed group;
4. reads one halfword from each of the other two gain arrays and one byte
   from the third;
5. packs three words;
6. calls `phy_write_gain_mem(words..., wrapping(base + entry))`.

The word packing is exactly the one implemented by
`encode_phy_gain_memory_words`:

```text
word0 = config[12:0] | seed2 << 22 | seed1 << 31 | seed3 << 13
word1 = seed0 << 8 | seed1 >> 1
      | ((gain64 >> 6) & 0xff) << 17
      | (gain72 & 7) << 31
      | (gain64 & 0x3f) << 20
      | 0x10000000
word2 = ((gain72 & 7) >> 1)
      | ((gain72 >> 1) & 0x1c)
      | gain32 << 15
      | 0x00007f80
```

Rust `publish_phy_tx_gain_memory` reproduces the 32-entry Wi-Fi image and
the ROM `phy_write_gain_mem` transaction exactly. Complete parity fails
because Rust always publishes 32 entries from `PhyWifiTxGainImage`, narrows
the bank to a Boolean, and has no general pointer/count implementation. It
also uses the Wi-Fi `phy_txbbgain_to_index` mapping for its typed image and
does not implement the distinct BT input/table contract.

## `phy_wifi_set_tx_gain_new`

Size `0x72`. Strict status: **MISMATCH**.

The function copies six consecutive words from
`phy_param[0xa8..=0xbf]` to a local seed image. It calls callback slot
`g_phyFuns[9]`, which resolves to `phy_wifi_get_tx_tab_new`, with the original
channel and diagnostic inputs and three local output arrays.

It then reads `phy_param[7]`. Zero calls:

```text
phy_set_tx_gain_mem_new(
    bank = 0,
    count = 32,
    generated halfword table,
    generated halfword table,
    generated byte table,
    copied seed plus adjacent generated data,
    phy_param + 0xd0
)
```

Every nonzero byte skips gain-memory publication but still performs the
callback and table calculation.

The Rust channel transition preserves this behavior for its accepted Wi-Fi
channel profile, including calculation before the skip decision and exact
32-entry publication. It is not a complete replacement for the standalone
vendor function: the enclosing Rust owner rejects vendor channel/frequency
domains outside its AP/STA profile and exposes no general two-argument
entry. This profile narrowing is not a vendor defect.

## `phy_bt_get_tx_tab_new`

Size `0xa8`. Strict status: **NO-REGISTER-EFFECT**.

The function copies all three 36-byte BT tables from `.rodata` to its stack.
It reads:

- `phy_param[8]`;
- `phy_param[0x124]`;
- signed `phy_param[0xfe]`;
- the calibration bytes beginning at `phy_param + 0xfb`.

It passes the signed low byte of
`phy_param[0x124] - phy_param[8]`, the caller buffers, the three copied
tables, and fixed stack arguments `-96`, `3`, `80`, and `-72` to complete ROM
`phy_bt_get_tx_gain`.

The ROM child and its saturation/table-selection children are pure and
perform no MMIO. Rust has no BT table-generation owner, but this wrapper
itself has no direct or transitive register effect.

## `phy_bt_set_tx_gain_new`

Size `0x66`. Strict status: **NOT-PORTED**.

The function copies six words from `phy_param[0x104..=0x11b]`, calls callback
slot `g_phyFuns[10]` (`phy_bt_get_tx_tab_new`) with three local output arrays,
then unconditionally calls:

```text
phy_set_tx_gain_mem_new(
    bank = 1,
    count = 16,
    generated BT tables,
    copied BT seed plus adjacent generated data,
    phy_param + 0xd0
)
```

No Rust transition generates these BT tables or publishes the 16-entry bank-1
gain image.

## `phy_bt_tx_gain_init`

Size `0x5a`. Strict status: **NOT-PORTED**.

The complete, branch-free call order is:

1. `phy_set_channel_rfpll_freq(0x985, phy_param[0x4f], 0)`;
2. `phy_set_txcap_reg(phy_param + 0xdc, 6)`;
3. `phy_bt_txdc_cal_new()`;
4. `phy_bt_tx_pwctrl_init()`;
5. `phy_txdc_cal_pwdet_init(1, 0, 1)`;
6. tail-call `phy_bt_set_tx_gain_new(0)`.

This mandatory child of archive `phy_bb_init` is absent from the Rust parent.
Some generic RFPLL, TXDC and PWDET leaves exist, but the BT-specific
calibration state, ordering and final gain publication do not.

## `phy_wifi_get_tx_tab_new`

Size `0xa0`. Strict status: **NO-REGISTER-EFFECT**.

The function copies the three 36-byte Wi-Fi tables from `.rodata` offsets
`0x6c`, `0x90`, and `0xb4`. Those 18-halfword tables exactly match
`WIFI_TX_GAIN_TABLE_LOW`, `WIFI_TX_GAIN_TABLE_MID`, and
`WIFI_TX_GAIN_TABLE_HIGH`.

It computes the signed low byte of
`phy_param[0x123] + phy_param[0x1b2]`, reads signed correction byte
`phy_param[0xf7]`, and calls complete ROM `phy_wifi_get_tx_gain` with:

- the original channel and diagnostic input;
- calibration curve `phy_param[0xf1..]`;
- the three fixed tables;
- the three caller output buffers.

The ROM graph is pure. `calculate_wifi_tx_gain` reproduces the interpolation,
32 descending target values, table search and packed outputs; only
diagnostic printing is omitted. The wrapper and its children have no register
effect.

## `phy_set_tx_cfr_mem`

Size `0x76`. Strict status: **MISMATCH**.

The function first reads the high byte of `0x20100408`, even when the input
count is zero. Its byte loop supports every count in `0..=255`; values above
255 never compare equal after byte wrapping and make the vendor loop
nonterminating.

For every finite entry:

1. full-store `0x00000e13` to `0x20100848` for indices `0..=9`, otherwise
   full-store zero;
2. fresh-read `0x20100844`, replace bits 18:11 with
   `wrapping(base + index)`, and write it;
3. fresh-read the same register, set bit 21, and write it;
4. fresh-read it again, clear bit 21, and write it.

`PhyTxCfrTransition` plus the PAC preserve this exact trace for the cold
call `phy_set_tx_cfr_mem(32)`. Rust fixes the count at 32 and cannot reproduce
the other finite vendor counts, so the complete function is a strict
mismatch. The vendor's nontermination above 255 does not justify narrowing
the valid finite domain.

## Member conclusion

The current Wi-Fi cold profile has exact table constants, TX-gain packing,
gain-memory writes and 32-entry CFR publication. Complete member parity is
absent:

- general count/bank/table inputs are narrowed to one 32-entry Wi-Fi image;
- CFR publication is fixed at 32 instead of the complete finite count domain;
- BT table generation, calibration composition and 16-entry publication are
  missing;
- the Wi-Fi setter exists only inside the restricted channel owner.

No difference in this member is a vendor-defect exception.
