# Unsafe boundary

The public driver and every protocol, policy, register-transaction, HAL, PHY,
MAC-backend and runtime-adapter APIs are safe Rust. New driver crates must put
`#![forbid(unsafe_code)]` in their library root.

Four implementation foundations are exceptions:

- `chips/esp32s31/pac` is generated by `svd2rust` and owns volatile MMIO pointers;
- `common/dma` proves stable addresses and exclusive CPU/radio ownership of generic
  pinned storage;
- `chips/esp32s31/wifi/dma` owns the chip descriptor layout, live RX ring and TX
  publication tokens;
- `adapters/embassy/esp32s31-platform` owns the linker sections, exported
  Embassy ABI symbols and reserved software interrupt used by the executor.

The three handwritten foundations use `#![deny(unsafe_code)]`. They may reopen
the lint only on the smallest item or expression that implements one audited
invariant, and every allowance must carry a non-empty `reason`. A crate- or
module-wide `#![allow(unsafe_code)]` is forbidden.

This boundary does not claim that DMA or an interrupt runtime can be
implemented without unsafe Rust. It makes those unavoidable proofs explicit
and prevents protocol or chip policy from acquiring raw pointers, unchecked
lifetimes or interrupt ownership.

## Active-owner destruction

Safe Rust cannot make a type non-droppable. The driver therefore gives every
asynchronous hardware actor an explicit close edge and a fail-closed final
guard:

- a live RX ring must pass through `try_stop`;
- an active interrupt epoch must pass through `quiesce`;
- ordinary and aggregate TX storage must receive a queue-detach proof, or be
  retained for the platform reset path.

Dropping a still-active RX, IRQ or TX authority panics; target release builds
use panic-abort. Aggregate network backings are forgotten before this guard so
unwinding cannot return memory which hardware may still address. Explicit
`core::mem::forget` can always leak an affine Rust value, but it neither runs a
destructor nor releases/reuses the underlying static DMA allocation.

Run the fast policy check from the repository root:

```text
tools/audit-driver-safety.sh
```

`tools/audit-source-only.sh` also invokes this check before its target build
and final-image dependency audit.
