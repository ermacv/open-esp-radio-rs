# ESP32-S31 IEEE 802.15.4 ED completion and selected status write

Date: 2026-08-25

This record preserves a bounded hardware observation of `ED_START`,
`ED_DONE`, TIMER0 and two selected writes to the ESP32-S31 IEEE 802.15.4
`EVENT_STATUS` register. It does not classify the complete register and does
not qualify an operational RX/TX dataplane or calibrated RF measurements.

## Setup and observations

Each boot used the ordinary source-derived sequence through radio power,
IEEE 802.15.4 clock readback, MAC/APB reset, interrupt-masked foundation and a
read-back-checked static policy on channel 11. It installed no CPU interrupt
route and started no DMA.

All three boots produced the same status relation:

| Checkpoint | Value |
| --- | ---: |
| Entry `EVENT_ENABLE` | `0x0000` |
| Active `EVENT_ENABLE` | `0x0150` (`RX_ABORT`, `ED_DONE`, TIMER0) |
| Active `RX_ABORT_ENABLE` | `0x03800000` (ED abort/stop/coex reject) |
| Active and terminal ED duration | `8` |
| Latched `ED_DONE` plus TIMER0 | `0x0140` |
| After writing only `ED_DONE` (`0x0040`) | `0x0100` |
| After writing only TIMER0 (`0x0100`) | `0x0000` |
| Final `EVENT_STATUS` | `0x0000` |

TIMER0 advanced from zero to the bounded threshold on every boot. No RX abort
was observed, no best-effort STOP was needed, both event-delivery masks ended
at zero, and source-132 route words for both cores remained zero before event
enable, while enabled and after cleanup.

This proves that the open source-derived MAC clock/reset/policy sequence is
sufficient on this hardware cell for one bounded `ED_START` to terminate with
`ED_DONE`. Under the same closed transaction, writing only `ED_DONE` cleared
that bit while retaining TIMER0, and writing TIMER0 then cleared TIMER0. It is
usable evidence for a finite ED completion path and these two selected status
writes; it is not a whole-register access-class claim.

## Explicitly not proven

The schema-1 result retains this exact `not_proven` list:

- `full-register-w1c-semantics`;
- `non-ed-event-write-semantics`;
- `concurrent-same-bit-arrival`;
- `level-triggered-route-behavior`;
- `production-phy-rf-btbb-readiness`;
- `synchronous-stop-semantics`.

The cell also does not assign physical units to the ED RSS code, validate RF
retuning or calibration, classify an active IRQ route, exercise RX/TX DMA, or
prove that an event bit can be acknowledged safely while the same bit arrives
again. Production code must keep broader `EVENT_STATUS` write semantics
unknown until each required event class and the concurrency case have their
own evidence.
