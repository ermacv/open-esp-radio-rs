# Unsafe boundary

The public driver and every protocol, policy, register-transaction, HAL, PHY,
LMAC and runtime-adapter API are safe Rust. New driver crates must put
`#![forbid(unsafe_code)]` in their library root.

Four implementation foundations are exceptions:

- `esp32s31/pac` is generated by `svd2rust` and owns volatile MMIO pointers;
- `dma` proves stable addresses and exclusive CPU/radio ownership of generic
  pinned storage;
- `esp32s31/wifi/dma` owns the chip descriptor layout, live RX ring and TX
  publication tokens;
- `integration/esp32s31/embassy-runtime` owns the linker sections, exported
  Embassy ABI symbols and reserved software interrupt used by the executor.

The three handwritten foundations use `#![deny(unsafe_code)]`. They may reopen
the lint only on the smallest item or expression that implements one audited
invariant, and every allowance must carry a non-empty `reason`. A crate- or
module-wide `#![allow(unsafe_code)]` is forbidden.

This boundary does not claim that DMA or an interrupt runtime can be
implemented without unsafe Rust. It makes those unavoidable proofs explicit
and prevents protocol or chip policy from acquiring raw pointers, unchecked
lifetimes or interrupt ownership.

Run the fast policy check from the repository root:

```text
tools/audit-driver-safety.sh
```

`tools/audit-source-only.sh` also invokes this check before its target build
and final-image dependency audit.
