# ESP32-S31 production WPA2 port qualification

Qualification ID: `HIL_ESP32S31_WPA2_PORT_2026_08_04`

Scenario: `radio` / `open-radio-hil`  
Profile: `psram-code-psram-data`  
Device: ESP32-S31 revision 0.0  
Runtime CRC32: `9e080a3b`  
Application image: 1,194,640 bytes  

This cell requalifies the WPA2 owner boundary after the ESP32-S31 handshake
and key-publication composition moved out of `radio_hil.rs` into the production
`wpa2_port` module. `Esp32s31Wpa2HandshakePort` now owns:

- retained RX/DMA binding and allocation-free EAPOL extraction;
- selected local/BSSID filtering and owned EAPOL copy;
- RX service/restart/stop transitions around Message 1 and Message 3;
- unprotected Message 2 publication and bounded transmission telemetry.

`Esp32s31Wpa2KeyPort` now owns:

- atomic pairwise/group CCMP installation and partial-install cleanup;
- supplicant-request-to-hardware-slot binding;
- typed unprotected or pairwise-protected Message 4 policy;
- sequence/CCMP-PN selection, TX status validation and rollback;
- return of the exact PTK/GTK authorities and TX completion evidence.

The HIL-specific `RadioHilWpa2Backend`, `RadioHilWpa2KeyBackend`, EAPOL TX
helpers and key installation code were removed. The older direct protected-ARP
probe was removed as well: it built another protected frame, advanced CCMP PN,
walked/recycled RX DMA and decapsulated data outside the production connected
driver. Successful M4 now hands the exact stopped RX owner, TX descriptor,
sequences and key authorities directly to `run_connected_network`.

All 113 `open-esp-radio-esp32s31-wifi-embassy` host tests passed, including the
new selected-link EAPOL extraction test and the existing handshake deadline,
replay, key-install, M4 failure and rollback contracts. `cargo hil build radio`
passed placement and autonomous-source-graph audits. The final image was
flashed through `/dev/ttyACM0`, then:

```text
cargo hil station reconnect --serial /dev/ttyACM0 --cycles 3 --timeout-seconds 120
```

completed all three cycles. Initial and repeated epochs each completed WPA2
Message 1 through Message 4, returned pairwise slot 4 and group slot 1, entered
the production connected runner, performed a 13-channel running scan with
13/13 successful Probe transmissions, and completed fresh Authentication,
Association and WPA2. The descriptor base remained `0x2f03e9d0` across every
returned generation and every frontier was empty. No direct protected-ARP HIL
stage exists in this image.

The transient UART evidence had SHA-256
`9401c0c7d2e730715ce23b28f6996d997b762d5ea89c556d10ae7238953a3946`.
Credentials were runtime-provisioned and are absent from the image/report.

This proves the concrete WPA2 ports and the direct M4-to-connected ownership
handoff. It does not prove injected install/TX failures on hardware, real AP
loss recovery, or extraction of peer programming and outer connected-session
composition from HIL.
